AUDIT TASK 1 — INDEXEDDB DELETION CORRECTNESS
Inspect /src/services/indexedDb.ts and every call site of safeDeleteOfflineDB(). Verify:
- It attaches onsuccess, onerror, and onblocked handlers.
- It treats onblocked as pending/failure, never as successful deletion.
- Timeout does not report success and does not silently continue as if storage were deleted.
- Every caller checks the returned {success, reason} result and enters a safe failure state on false.
- Active IndexedDB connections have onversionchange handlers that close connections.
- Broadcast messages to close connections are actually received and handled by every relevant tab/module; do not count merely posting a message as successful closure.
- Multiple DB names are actually used by this app and are not guessed or deleted unnecessarily.
