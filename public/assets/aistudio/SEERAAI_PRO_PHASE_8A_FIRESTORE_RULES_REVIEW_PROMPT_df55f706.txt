6. MINIMAL PATCH PROPOSAL — NO FILE EDITS
============================================================

Prepare a minimal unified diff proposal for firestore.rules, but DO NOT apply it.

Requirements:
- Fix only verified defects.
- Preserve all existing intended authorization boundaries.
- Never replace a broken helper with a broader allow condition.
- Never use allow read, write: if true for convenience.
- Never grant all authenticated users access to court or institutional records.
- Preserve institution isolation and user ownership checks.
- Ensure one institution cannot read another institution's records.
- Ensure one user cannot read another user's private documents or drafts.
- Separate public-read legal-source collections from private and institutional collections.
- Deny unknown roles by default.
- Reject missing or malformed authorization claims safely.
- Validate immutable ownership and institution fields on update.
- Validate request.resource.data on create and updates.
- Avoid a broad wildcard match that overrides a more restrictive policy.
- Keep the patch small and explain each changed condition.

For each proposed change, include:
1. current rule and exact location;
2. verified defect;
3. proposed replacement;
4. security effect;
5. possible compatibility impact on existing users/features;
6. required approval owner;
7. tests required before adoption.

If the current codebase does not establish the intended policy, do not guess. Mark that part BLOCKED — POLICY DECISION REQUIRED and provide the exact question the authorized reviewer must answer.
