5. STAGES 2–4 — AUTH, STORAGE, OFFLINE, BROWSER, MULTI-TAB, SERVICE WORKER
======================================================================

Inspect the current implementation and then run real browser tests with synthetic accounts and disposable browser profiles wherever the tooling exists.

Required cases:
1. Clean sign-out with no pending records.
2. Pending queue: sync succeeds; only server-confirmed data may be purged.
3. Pending queue: network loss; no silent deletion; data remains recoverable.
4. Local-only draft: no cloud destination; must remain pending and require explicit informed choice.
5. Corrupt JSON, unknown schema version, failed IndexedDB read, unavailable IndexedDB, and timeout; all destructive actions must fail closed.
6. IndexedDB `onsuccess`, `onerror`, `onblocked`, timeout, overlapping deletion request, and late settlement in real Chromium where possible.
7. Every database opener sets `onversionchange` and closes connections; verify application tabs and Service Worker handles.
8. Cross-tab protocol: enumerate live tabs; verify PREPARE, ACK, CLOSE_IDB, ACK_CLOSE, SESSION_TERMINATED; no timeout may be treated as an ACK.
9. Unresponsive/frozen tab: sign-out enters safe hold or isolation lockdown; a second user must not enter until isolation is verified.
10. Service Worker pause/resume and close-IDB messages; verify correlation IDs and actual acknowledgements.
11. Account A signs out, account B signs in; verify no A documents, titles, credentials, court session, role claims, bookmarks, drafts, annotations, or private cache are accessible to B.
12. All logout call sites (navigation, admin, court dashboard, session management, security dashboard, direct routes) must use the same guarded flow. No bypass via raw `signOut(auth)` or localStorage removal.
13. Verify default modal consent is non-destructive, inventory counts are real, discard requires two explicit steps, and cancel/stay-signed-in preserves data.
14. Verify sign-out failure: auth.currentUser, React state, persistence, lockdown, retry, and account-switch behavior remain consistent.
15. Verify local backups: prominently disclose plaintext versus encrypted state; never call an unencrypted JSON file secure/encrypted. Do not export real data during tests.
16. Check every sensitive localStorage key, IndexedDB store, cache, service-worker cache, sessionStorage key, and user-scoped namespace. Preferences must be allowlisted; do not preserve sensitive fields accidentally.
17. Verify exact storage key names from source (including `seera_device_auth_salt`); no guessed key names.

Required invariant: A sign-out flow must never silently destroy unsynced/local-only data, must never permit the next user to read the prior user's plaintext data, and must never treat a failed/blocked purge as successful isolation.

If these requirements cannot all be met simultaneously for a shared device, the safe outcome is to block account switching until the user has synced, securely exported, or explicitly confirmed permanent discard. Do not leave plaintext private data available to the next account.
