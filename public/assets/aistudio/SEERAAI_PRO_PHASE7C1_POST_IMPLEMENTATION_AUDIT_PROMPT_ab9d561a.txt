B. CRITICAL DATA-LOSS REVIEW — MUST PASS BEFORE ANY DEPLOYMENT
Trace the full sign-out flow from the UI action through AuthContext and all called services. Determine whether the current implementation:
1. Prevents new local writes and pauses/coordinates background sync while sign-out is in progress.
2. Waits for in-flight sync/write operations safely.
3. Enumerates ALL relevant unsynced queue entries and local-only drafts, not merely one queue or one key.
4. Distinguishes cloud-confirmed records from queued-but-unsynced and local-only records. A missing queue item is NOT proof that a draft is safely stored in the cloud.
5. Verifies server/cloud acknowledgment before purging any pending data.
6. When sync fails or the device is offline, keeps the user signed in and preserves all unsynced work unless the user explicitly confirms a clearly worded discard action.
7. Requires a second explicit confirmation for “Discard Unsynced Changes & Sign Out,” and clearly identifies that unsynced work will be permanently removed.
8. Deletes only explicitly enumerated SEERAAI-owned keys and stores. Check whether broad prefix deletion such as all keys beginning `seera_ai_` or `seera_offline_` could delete unrelated, future, or still-needed data.
9. Handles IndexedDB open connections, blocked deletion, transaction errors, and deletion failure. Do not treat a requested delete as proof that the database was deleted.
10. Prevents a different user/account in another tab from seeing the prior user's cached data. Check BroadcastChannel/storage-event behavior, auth-state propagation, and failure handling.
11. Does not redirect to login or permit another account to sign in while sensitive prior-user data remains accessible after a purge failure.

For every item, mark PASS / FAIL / NOT VERIFIED and cite exact file paths and line ranges. Explain any data-loss path plainly.
