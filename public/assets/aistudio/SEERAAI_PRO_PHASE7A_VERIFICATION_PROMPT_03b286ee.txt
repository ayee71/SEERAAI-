B. CRITICAL DATA-STORAGE REQUIREMENT
The existing project requirement is that actual user/court documents must not be stored in localStorage, IndexedDB, GitHub, or browser base64 caches as their document repository. Firebase Storage must hold document binaries; Firestore must hold authorized metadata and references.

Search the entire codebase for IndexedDB, localStorage, sessionStorage, base64, Blob, Cache API, service-worker caches, and offline sync. Return:
1. Exact file paths and line numbers where document content or sensitive metadata is cached.
2. What data is cached, for how long, and whether it is encrypted.
3. Whether a public user can access a previously cached institutional/court document on a shared device or after signing out.
4. A safe remediation plan that preserves existing records and functionality.

Do not delete any existing cache or document. Distinguish harmless UI preferences from actual document content. If offline court-document access is required, do not assume ordinary IndexedDB caching is acceptable; identify the security design and obtain approval before implementation.
