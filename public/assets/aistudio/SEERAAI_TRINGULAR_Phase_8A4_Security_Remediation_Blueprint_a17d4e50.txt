6. REQUIRED SECURITY DESIGN

Prepare a secure target architecture with the following principles:

Authentication

- Authenticated users only where authentication is required.
- Secure user identity verification.
- No trust in client-supplied identity or role values.

Authorization and RBAC

- Server-enforced role verification.
- Institution-scoped permissions.
- Least-privilege authorization.
- Explicit protection of administrative and privileged roles.
- Users must not be able to assign themselves privileged roles.

Institutional and Tenant Isolation

- Users must only access data authorized for their institution.
- Court documents, cases, evidence, judgments, orders, and audit records must be protected by institution and role.
- No cross-institution access unless explicitly authorized.

Firestore

- No broad public or authenticated-user-only access to confidential collections.
- No unconditional permissions for sensitive data.
- Validate document ownership, institution identity, role, and permitted operations.
- Protect sensitive fields against unauthorized modification.

Storage

- Align Storage Rules with the exact paths used by the application.
- Enforce authorization on uploads, downloads, updates, and deletions.
- Apply appropriate file-size and file-type restrictions.
- Preserve existing stored files.
- Do not introduce an alternative storage mechanism without analyzing its security and data-integrity consequences.

Backend and Admin SDK

- Verify authorization independently on trusted backend operations.
- Do not rely on Firestore Rules as protection for Admin SDK operations.
- Validate institution scope and role before processing sensitive requests.
- Protect audit operations against unauthorized modification.

Audit and Monitoring

- Preserve meaningful audit records.
- Record sensitive access and administrative actions where supported.
- Protect audit logs from unauthorized alteration or deletion.
- Recommend appropriate monitoring and alerting.
