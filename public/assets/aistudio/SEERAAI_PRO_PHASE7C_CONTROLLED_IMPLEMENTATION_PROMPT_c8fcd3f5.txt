PATCH A — SAFE SIGN-OUT AND ACCOUNT SWITCH
Implement the smallest safe change possible, based on verified source APIs.

Required behavior:
1. Add a sign-out operation lock before beginning cleanup. Prevent new local writes and prevent a second simultaneous sign-out/account switch while cleanup is running.
2. Pause or coordinate background sync and safely await any already-running write/sync operation using the existing implementation. Do not invent an API or silently cancel a write.
3. Inspect every pending offline edit and any local-only draft/cache that could contain user data. A zero-length sync queue alone does NOT prove that every local document is safely stored in the cloud.
4. Distinguish confirmed cloud-synced records from pending-unsynced and local-only records. Only remove a record after confirming it is synced, or after the user explicitly confirms discarding the identified unsynced/local-only work.
5. When pending/local-only user work exists, show clear options: “Retry Sync”, “Stay Signed In”, and “Discard Unsynced Changes & Sign Out”. The discard option must require a separate explicit confirmation and identify the consequence. No automatic discard.
6. If sync fails or the network is unavailable, keep the user signed in unless the user explicitly confirms discard. Do not purge unsynced data.
7. Purge only verified SEERAAI-owned, user-sensitive cache keys and records belonging to the departing user. Preserve non-sensitive preferences such as language/theme. Do not clear all localStorage or delete the entire IndexedDB database unless source inspection proves that doing so cannot remove another user's data or unrelated app state.
8. Include the relevant IndexedDB stores in the cleanup design where appropriate. Ensure transactions complete successfully and verify deletion. Do not report cleanup success if any deletion failed.
9. Handle multi-tab sign-out/account switching with the existing browser mechanisms (BroadcastChannel and/or storage events) only if compatible with the current code. Ensure another tab cannot continue displaying the previous user's cached documents after sign-out.
10. If cleanup fails, fail safely: do not allow a different account to read the previous user's local cache. Keep the app in a restricted cleanup-required state or use another verified safe approach. Do not simply redirect to login and claim that local data has been removed.
11. Ensure error handling does not expose private document contents in logs.
12. Do not alter server authorization, Firebase rules, roles, or production storage paths in this phase.
